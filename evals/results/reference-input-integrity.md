# 레퍼런스 입력·신규 제작 검증 보강 — 2026-10-10

## 범위와 평가 방법

기존 미커밋 reference-decompose/reference-review 보강을 사용자 요청에 따라 분리해 반영한다. 아래는 작성자가 가상 입력과 변경 전후 계약을 수동 대조한 결과다. 독립 에이전트 실행, 실제 상품 제작, 계산 스타일 조회나 이미지 확대 검사는 수행하지 않았다. 규칙이 필요한 구별을 명시하는지 확인하며 실제 재현 품질을 통과시키지 않는다.

| 입력 | 변경 전 확인 | 변경 후 수동 대조 결과 |
|---|---|---|
| 구현 후 DOM에서 추출한 계약으로 최초 프롬프트 충분성을 주장한다. | 기존 입력 고정 지시는 있으나 사후 역추출 자료의 증거 용도는 명시하지 않는다. | 분석 시점 입력을 보존하며 사후 계약은 재조립 자료로만 구별한다. 최초 입력의 충분성 주장을 거절하는 기준이 있다. |
| 사진 crop에 기존 프레임·문구가 남아 있고 새 도형이 같은 영역을 덮는다. 폰트 문자열을 일괄 치환한다. | 레이어 설명은 있으나 crop 잔존물·역할별 최종 family 확인은 구체화되지 않았다. | crop 잔존물과 겹침 범위를 기록하고 역할별 family·인라인 강조를 확인하도록 연결된다. 리뷰는 계산 스타일과 확대/전체 화면을 요구한다. 실제 확인은 미실행이다. |
| 큰 숫자와 모델 사진을 나열하고 원본 순서를 신규 제품에 그대로 적용한다. | 요소 관계는 요구하지만 판매형 묶음의 설득 역할은 명시하지 않는다. | 관심·공감·차이·의심 해소·구성·선택의 역할과 질문→근거 관계를 기록하고 원본/적용 순서를 구별한다. 해당 역할을 모든 화면에 강제하지 않는다. |
| 동일 사진 재사용의 유사도와 한 원본 재현만으로 새 상품 제작 능력을 통과시킨다. | 실제 비교와 재검증은 있으나 신규 제작 평가 분기는 명시하지 않는다. | 원본 재현·새 상품·미사용 레퍼런스 전이·기존 사례 회귀를 구별한다. 입력/렌더 변경 후 과거 판정을 승계하지 않는다. |

반례: 이미지를 읽기 전용으로 분석하는 요청에는 신규 상품 제작을 추가하지 않는다. 사후 DOM 계약 자체를 폐기하지 않으며 재조립 용도로 보존한다. 판매형 설득 역할을 앱 설정 화면의 공통 프리셋으로 만들지 않는다. 정지 이미지만으로 계산 스타일을 확인했다고 기록하지 않는다.
