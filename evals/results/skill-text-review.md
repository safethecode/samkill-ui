# 스킬 본문 검토와 오류 수정

검토일: 2026-10-11. 앞선 문자 검색만으로 끝내지 말고 실제 잘못된 표현과 지시를 찾아 수정하라는 사용자 요청에 따른 후속 검토다.

## 범위와 발견

관리 원본 skills/의9개 SKILL.md와 참고/작성 틀33개, 총42개 Markdown을 읽고 문맥·지시·범위·연결을 대조했다. 잘린 도구 출력은 누락된 구간을 다시 읽었다. 메타데이터8개와 코드/JSON을 포함한 텍스트52개의 문자·인코딩 검사도 구별한다. 다른 저장소/플러그인과 기존 데모의 UI 재검증은 이 검토 범위가 아니다.

| ID | 실제 문제 | 수정과 근거 |
|---|---|---|
| TEXT-01 | onboarding-flow 본문에 `missing 정보`가 문장 일부로 남음 | ‘정보가 부족해도’로 교정. 정보가 없어도 독립 작업을 진행하는 의미는 유지. |
| TEXT-02 | 이메일 가입 예시의 응답 유실에 ‘결제/가입 결과’가 남음 | 예시의 실제 대상인 ‘가입 결과’로 정리. 결과 미상과 안전한 확인 절차는 유지. |
| STATE-01 | 토큰 계약은 선택 불가를 ‘disabled와 구별되는 표현’으로 지시함 | 기본·선택과 구별되는 비활성 표현과 실제 선택 차단으로 명확히 함. 기존 재발/상태 기준의 native disabled 또는 ARIA+이벤트 처리와 일치. |

변경은5개 문제, 스킬 문서5개에 한정한다. 새 금지 규칙·catalog 버전·게이트 판독기를 추가/변경하지 않는다. 과거 중간 편집의 잘못된 한자/일본어 혼입은 세션 기록에 보존하며 현재 파일의 문자 검색0건으로 그 이력을 부정하지 않는다.

## 평가와 검증의 구별

- SKILL-REVIEW-01: 명세·읽기 전용·쓰기 가능한 구현의 세 범위를 문서상 대조했다. 실제 CLI의 ledger 선택 인자와 출력/기록 분기를 코드에서 확인했다.
- SKILL-STATE-01: 기존 재발 점검·연속 상태 기준과 대조해 표현뿐 아니라 선택 차단이 필요함을 확인했다. 실제 예약 UI의 수정/렌더/보조 기술 시험은 수행하지 않았다.
- SKILL-REVIEW-02: catalog의 활성 RUI-24/25 및 상세 리뷰 기준과 진입점의 검사 범위를 대조했다. 기존 동작/규칙을 새로 일반화한 결과가 아니다.
- 위 사례는 작성자의 수동 계약 대조다. 독립 모델의 스킬 실행 성공이나 모든 제품의 품질 개선 증거로 부르지 않는다. 파일/CLI 검사의 실제 결과는 아래에 추가한다.

## 실제 실행 결과

- 관리 원본9개 스킬의 quick_validate 통과. 텍스트52개의 엄격 UTF-8·문자 검사에서 현재 혼입/깨짐 후보0건, YAML8개/JSON1개 구문 정상.
- 스킬 Markdown42개와 평가 사례·이번 결과·세션 기록의 로컬 링크 경로247개, 제목 앵커35개 통과. 코드 블록/인라인 코드의 링크 양식 예시는 실제 경로와 구별했다. 신규 결과 파일을 포함한 공백 검사와 git diff --check 통과. 외부 웹 링크의 현재 접근성은 이번에 재검증하지 않았다.
- 실제 기존 Round11 계약/보고서로 design_gate.py check를 **--ledger 없이** 실행: PASS/exit0, errors/failures0. 실행 전후 대상 디렉터리 파일1051개의 경로·내용 SHA-256이 같음을 확인했다. 이는 기존 판독 기록의 CLI 무결성과 읽기 전용 실행 검증이며, 새로운 UI 렌더·행동 판독 결과가 아니다.
- 판독기 Python과 catalog는 변경하지 않았다. 새 단위 테스트를 추가하거나 판독기 동작을 바꾼 작업이 아니며, 미실행 독립 평가를 통과했다고 보고하지 않는다. 이번 수정은 로컬에 유지한다.
