# Primary 컬러 선택 기준 보강 — 2026-10-10

## 사용자 교정과 변경 전 공백

사용자는 Primary 컬러를 잘 선택하지 못하는 것 같다고 지적했다. 특정 화면·색값·레퍼런스는 지정되지 않았다. 기존 토큰 계약은 역할·전경·상태·대비를 구체적으로 요구하고 스타일 계약은 명도·채도·면적 관계를 다루지만, 새 Primary 후보의 선택 근거와 실제 화면에서 적합성을 판단하는 절차는 여러 문서에 흩어져 있었다. 이를 특정 과거 제품의 색 실패나 그 원인이 확정된 증거로 쓰지 않는다.

선택: primary-color 참고 문서를 추가해 제품/내용·기존 브랜드·레퍼런스 관계를 후보 선택과 연결했다. 색 역할·명도·채도·표면·전경·사용 면적을 실제 핵심 화면에서 확인한다. 문서 예시 HEX나 업종 고정관념을 기본값으로 쓰지 않으며, 무채색·저채도·기존 파랑 자체를 금지하지 않는다. 색이 실제 판단 과제일 때만 후보 비교를 수행하고 후보 개수·면적 비율·사용자 승인 단계를 고정하지 않는다.

## 작성자 수동 계약 대조

아래는 가상 입력을 변경 전후 지침에 대조한 결과다. 독립 에이전트 실행이나 실제 색 후보 렌더·선호 실험은 아니다.

| 가상 입력 | 새 기준에 따른 선택/판단 |
|---|---|
| 브랜드가 없는 새 앱에 토큰 예시 파랑을 그대로 사용하고 ‘신뢰감’이라고 설명 | 예시·업종·형용사만으로 선택하지 않는다. 제품 내용과 확인한 레퍼런스 관계를 근거로 후보를 정하고 판단이 갈리면 같은 핵심 화면에서 비교한다. 파랑을 자동 배제하지도 않는다. |
| 사진의 초록을 CTA에 옮겼는데 사진 옆에서 조작이 묻힘 | 사진의 색 빈도와 조작 식별 역할을 구별한다. 색상 계열·명도/채도·표면·사용 면적 중 어긋난 관계를 확인하고 필요한 역할을 바꾼다. 무조건 보색으로 바꾸지 않는다. |
| 대비 수치는 통과했지만 CTA·제목·배지·카드를 같은 색으로 칠함 | 대비와 행동 위계를 따로 판단한다. 시선·반복·면적·행동 범위를 확인하고 실제 필요한 강조를 보존한다. 고정 배색 비율로 기계적으로 줄이지 않는다. |
| 승인된 밝은 브랜드색의 버튼에 흰 글자가 읽히지 않음 | 브랜드 제약을 보존하며 전경·행동 역할별 명도·배경 등의 대안을 실제 색쌍으로 검사한다. 모든 Primary 역할을 어두운 색으로 일괄 치환하지 않는다. |
| 무채색 레퍼런스의 문서 도구를 정확히 재현 | 유채색을 추가할 필요가 없다. 명시 재현 범위와 원본 위계·표면 관계를 보존한다. |
| Primary 교정 요청만 있고 실제 화면은 없음 | 공통 판단 기준을 보강하고 가능한 원인을 구별한다. 특정 화면의 색 실패·수정 완료·시각 검증 통과를 주장하지 않는다. |

## 적용 범위와 검증

reference-to-ui, 토큰 계약, reference-review의 리뷰 기준, design-md의 문서 계약, samkill-ui와 루트 DESIGN에 연결했다. 기존 제품·브랜드값·catalog·판독기는 변경하지 않았다. 회귀 PRIMARY-01/02를 추가했다. 파일 검증 결과는 후속 기록에 남긴다. 실제 색 선택 품질·제품 렌더·상태별 대비·사용자 선호는 이번 문서 변경으로 입증하지 않는다. 커밋·푸시는 하지 않는다.

파일 검증 결과: 관련4개 스킬 quick_validate, 로컬 Markdown 링크 경로186개, 신규 대비 기준 앵커, 신규 파일 공백과 git diff --check 통과. 개인 설치 경로에서 변경 본문·신규 참고 문서가 관리 원본과 일치함을 확인했다. 기존 링크 전체의 앵커·실제 UI는 미검증이다.

## 후속: 사용자 자료·블로그와 흰 배경 요구

사용자는 브랜드 가치·색 연상·시장 구별·매체·팔레트·60-30-10을 설명한 글을 제공하고 [Jongmin Park의 UI를 위한 색](https://brunch.co.kr/@blckschrl/41)(2018-04-18)을 확인해 배색에 활용하라고 요청했다. 이어 기본 배경은 언제나 흰색이며 다크모드는 명령할 때만 쓰라고 명시했다.

실제 확인: 링크 본문과 아래6개 도해를 다운로드해 직접 관찰했다. 이미지 경로의 접근 오류는 HTML의 원본 이미지 주소를 읽어 해결했다. 사진의 녹색 UI, 배색 예시, 조절 도해가 입력 자료이며 동일한 UI를 구현한 평가가 아니다. 원본 UI의 밑줄·구분선·작은 글자는 채택 범위가 아니다. 색을 실제 CSS 값으로 복원하거나 비율을 픽셀 실측한 것으로 주장하지 않는다.

| 사용자가 다크모드를 명시 요청 | 해당 테마의 전경·배경·상태를 설계한다. 원본색의 단순 역전만으로 검증 완료라 하지 않는다. |

이는 작성자의 수동 계약 대조다. 실제 제품 화면에 새 팔레트/배경을 적용한 렌더·행동 검증과 독립 실행 평가는 미실행이다. AGENTS·DESIGN·관련 스킬·평가에 반영하며 커밋·푸시는 하지 않는다.
