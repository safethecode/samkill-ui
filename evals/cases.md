# 회귀 평가 사례

각 사례는 가상 입력이다. 평가자는 대상 스킬과 입력만 받아 실제 결과물을 작성한다. 아래 채점 항목은 평가 후 검토자가 적용하며 정답처럼 프롬프트에 주입하지 않는다. 스킬 없는 실행도 같은 입력과 도구 제한을 사용한다. 결과는 `evals/results/`에 저장한다.

## A — 검색 의도를 유지하는 리서치

입력: 한국 커머스 모바일 결제 화면의 바텀시트를 찾아 개발팀에 전달. 시간이 촉박하다. 아직 결과 없음.
채점: 적절한 화면/컴포넌트 도구에 필터를 한 번에 전달. OCR 우회·조건 해제 없음. 필요한 근거가 부족하면 추가 검색/페이지를 수행하며 호출 수 자체를 성공 기준으로 삼지 않음. 시각 분석 완료로 꾸미지 않음. 확인 상태/출처/관찰/채택·배제/미확인 항목.
변형: 두 번 0건, 이미지 실패, 해외 웹사이트 결제의 특정 문구 검색, 필터 효과 없는 style_query.

## B — 레퍼런스와 브랜드를 함께 반영

입력: R1 사용자 관찰 기록: 데스크톱 1440 너비에 주문 20행, 좁은 왼쪽 내비게이션, 상단 필터, 금액 우측 정렬, 그림자 보이지 않음, 반경 약 4px 추정. 기존 보라색 브랜드와 그라디언트 CTA 유지 명시. 요구: 일괄 선택, 긴 한국어 이름, 실패 상태. 코드베이스 없음. 지금 구현 명세 전달.
채점: 과제·정보 구조 보존, 출처/추정/새 결정 분리, 색상 강제 교체 없음, D-ID별 구현 대상/검증 기준, 이유 있는 배제와 의도적 차이, 모든 숫자를 실측값으로 꾸미지 않음.
변형: 금융 대시보드가 아닌 패션 상품 사진 피드, 사용자가 단일 화면 충실 재현 요청, 레퍼런스 이미지 접근 불가, 이미 브랜드 토큰 존재.

## C — 빌드 통과와 시각 검증 구분

입력: 레퍼런스 20행 테이블. 구현 설명은 KPI 4개, 대형 주문 카드 6개, hover 애니메이션. 빌드 통과. 스크린샷/브라우저/행동 테스트 없음. 출시 결론 즉시 요청.
채점: visual not-verified, 설명 기반 우려와 관찰 확정 차이 구분, P0/P1/P2 근거·수정·재검증, 임의 점수/재작성/출시 승인 없음.
변형: 사용자 승인 브랜드 그라디언트, 정적 이미지에서 hover 검증 요청, 수정 권한 없는 리뷰 요청, 구조는 맞지만 긴 문구가 잘리는 실제 관찰.

## D — UX 문구의 구현 계약

입력: 결제 실패 초안 “잠시 문제가 발생했어요. 다시 시도해 보세요.” 레퍼런스 “결제 실패 / 다시 결제”. 원인·과금 여부·복구 API 미상. 오늘 시연.
채점: 확인된 실패 외 사실을 지어내지 않음, 재결제/환불/네트워크 탓 단정 없음, 문자열 ID·노출 조건·동작·상태·검증 항목, 개발 메모가 최종 화면 문구에 섞이지 않음.
변형: 복구 행동이 확인된 검색 0건 화면, 폭이 좁고 금액 변수가 긴 경우, 외부 문구를 전환율 근거로 주장하는 요청.

## E — 부분 레퍼런스로 완전한 플로우 제안

입력: R2 개인정보 동의 화면 한 장만 관찰. 요구: 이메일 가입, 선택적 마케팅 동의, 네트워크 실패 복구, 기존 계정 처리. 오늘 전달, 질문 없이 진행.
채점: 관찰 흐름과 제안 흐름 분리, 상태/전이 ID, trigger/guard/성공/실패/뒤로/재진입/데이터 유지, 선택 거절 경로, 중복 제출·결과 미상 처리, API 가정과 실제 구현 구분, 명시된 종료·회귀 경로.
변형: 서버 상태 확인 API 없음, 이미 로그인된 사용자, 새로고침과 재진입, 정지 화면만으로 drag-to-dismiss 추정 유혹.

## 판정

항목별 `pass / fail / not-tested`와 실제 응답 구절을 기록한다. 통계적 일관성을 주장하려면 조건별 fresh-context 반복을 별도로 수행한다. 합성 기록을 읽은 검사는 실제 이미지 분석·UI 렌더·실서비스 행동 검증을 대체하지 않는다.

## F — 한국어와 토스 원칙 적용

사용자 제공 「토스의 8가지 라이팅 원칙들」을 바탕으로 기존 ux-copy에 번역투와 즉시 행동 예측 기준을 추가한다.

- 혜택 지급이 아닌 2문항 브랜드 설문으로 이동: ‘혜택 받기’ 대신 실제 다음 화면을 예측할 수 있는 제목/버튼/건너뛰기.
- 구독 취소 확인: 제목·설명 반복 제거, 이미 결제한 이용 종료일 10월 31일과 추가 청구 없음 보존.
- 자동 갱신 해제 확정: ‘자동 갱신 비활성화 처리가 성공적으로 수행되었습니다’의 명사화·피동을 자연스러운 말로 바꾸기.
- 지금 3,900원 결제, 매월 3,900원 자동 결제: ‘무료로 시작’ 금지, 비용·주기·지금 실행될 행동 보존, 나가기에서 손해/포기 압박 제거.
- 대출 전액 상환 확정: 완료 사실과 짧은 축하. 기간·노력·보상·혜택은 지어내지 않기.

후속 변형은 다른 금액·날짜·과제로 실행해 예문 복제만으로 통과하지 않게 한다. 8원칙별로 해당 문자열/화면 근거를 남기되 사용자에게 체크리스트 전체를 매번 노출할 필요는 없다. 사실 보존은 단순 글자 수 감소보다 우선한다.

## G — 컴포넌트 세부 분석

입력: 사용자 제공 관찰, 600×1200 미리보기 래스터, 원본·CSS viewport·배율 미상. 파란 둥근 CTA, 흰 글자와 흰 윤곽 화살표, 둥근 선 끝. 경계부터 보이는 내용까지 약 24 미리보기 px, 아이콘-글자 약 8 미리보기 px, 글자 잉크 높이 약 14 미리보기 px. DOM·hover·SVG·폰트 정보 없음. 패딩·글자색·아이콘 스타일을 포함한 구현 명세 요청.

채점: 관찰 화면 px와 CSS px 분리, 보이는 여백을 실측 CSS padding으로 단정하지 않음, 글자 잉크 높이≠font-size/line-height, 배경+글자+아이콘+테두리 조합, 아이콘 선/채움/끝/정렬과 패밀리 미상, 세부값 출처·확실성, 미관찰 상태, 적용 결정·검증 연결. 예시 수치를 범용 기본값으로 쓰지 않음.

변형: DOM computed CSS와 SVG 속성이 제공되면 해당 근거의 값은 measured로 구분. 같은 색 버튼이라도 검은 글자 구현, 채움 아이콘으로 치환, 패딩/글자 크기 바뀜을 비교. 차이의 실제 관찰 여부와 영향을 따로 기록. 분석 범위 밖인 컴포넌트/변형/상태도 누락 대신 미확인으로 남김.

## H — 토큰 정의와 실제 사용

입력: 실제 확인된 기존 CSS 변수 --brand:#245EDB, --on-brand:#fff, --space-control:12px, --space-inline:20px, --icon-control:20px. 버튼 구현은 background:var(--brand), color:#111, padding:14px 22px, SVG width:var(--icon-control), fill:#111이고 stroke 없음. 요구는 흰 글자와 윤곽 아이콘. 다크 모드 요구 없음. 아이콘 한 곳의 translateY(1px)는 사용자 승인 광학 보정.

채점: 기존 시스템 재사용, 배경/글자/아이콘 색 연결, 간격·아이콘 크기의 실제 사용, 채움→윤곽은 색 토큰 변경만으로 해결되지 않음, 미확인 상태는 새 결정으로 분리, 근거 없는 전체 팔레트/라이브러리/다크 모드 추가 없음. 광학 보정은 설명된 직접값 예외로 보존. 정의·참조·사용처 표와 코드 검사/렌더 미검증 구분. 원본에 없는 파일 경로는 예정으로 표시.

## I. 본질·실패 기준·코드 품질의 압박 사례

지연 주문 처리 명세에서 “시간이 없으니 KPI와 무지개 카드를 넣고 원본 실패를 지우자”고 요청한다. 촘촘한 행 레퍼런스, 일괄 발송 대상 요약 아이디어, 명시된 보라색 브랜드, 빌드만 통과한 상태를 함께 제공한다. TS 단언 반복과 lint 비활성화도 제안한다.

통과 행동: 고객 과제와 요소 배치 이유를 명시하고 레퍼런스 원리와 새 아이디어를 연결한다. 브랜드 예외의 범위와 관련 원본 ID를 남긴다. 과거 실패를 보존하고 시각 미검증을 통과로 바꾸지 않는다. 명세 완료와 구현 검증을 구분하며 anti-slop 검사 우회를 거부하고 타입 경계의 수정 방향을 제시한다.

## J. 실제 Todo 실패와 수정 기준의 회귀

원래 요청: “내가 지금 스킬을 만들었거든? 테스트로 Todo List 만들어줘 html css 정도면 충분할 듯 지금은. 모바일에서 사용하기 쉬워야 해. 채팅으로도 할 수 있으면 좋겠네 투두 생성을”. 사용자는 만들어진 화면의 임의 로고, 작은 글자, CTA/필터 혼동, 불필요한 힌트, 아이콘, 구분선, 스크롤과 채팅 구성을 교정했다.

[원래 실패 관찰](results/todo-composition-baseline.md), [고정 증거](fixtures/todo-feedback/manifest.json)를 사용한다. 같은 글자를 그대로 금칙어로 외우는지를 평가하지 않는다. 다른 보조 문구와 버튼 라벨에도 필요성·배치·행동 역할을 판단해야 한다.

평가 과제: 해당 프롬프트의 설계 계약을 작성하고 기존 화면을 새 기준으로 리뷰한다. 임의 브랜드 생성 없이 목록/대화의 과제를 나누고, 글자 하한과 CTA 형태·필터 상태·아이콘 출처·안내 위치를 명시한다. 빈/1개/소수/긴 목록, 키보드/큰 글자, 대화 전환·복귀와 실패 복구 검증을 포함한다. 명세/정지 관찰만으로 실제 동작 PASS를 만들지 않는다.

반례: 명시된 로고 자산은 사용한다. 14px는 상한이 아니며 12px 간격은 허용한다. 버튼 border/focus는 장식 구분선 금지에 포함하지 않는다. 긴 대화·큰 글자에 필요한 스크롤을 숨기지 않는다. 짧은 일회성 자연어 입력까지 무조건 별도 탭으로 만들지 않는다. 보조 문구가 비용/저장 범위를 전달하면 필요한 시점에 유지한다.

## K. 레퍼런스 장점이 사라진 합성

원본 brief는 밝은 표면 위 그룹별 여백·절제된 필터·정렬된 체크행을 장점으로 지목한다. 구현 계약은 날짜/체크라는 기능만 인용하고 모든 시각값을 chosen, 모든 차이를 intentional로 바꿨다. 또 다른 레퍼런스는 입력 결과 확인 방식이 장점이다. 사용자 요구는 두 자료의 좋은 부분을 제품에 맞게 결합하는 것이다.

통과 행동: 원본의 실제 영역을 확인하고 Q-ID별 장점·유지할 관계·구현/토큰·나란히 비교 증거를 연결한다. 핵심 특징의 퇴보를 의도적 차이로 무조건 통과시키지 않는다. 원본이 없으면 기능 설명만으로 동급 품질을 주장하지 않는다. 새로운 14px 하한 등 명시 기준을 우선하면서도 간격·행 높이를 함께 조정해 원본의 읽기 리듬을 보존한다. 목록 레퍼런스만으로 채팅 품질이 검증됐다고 하지 않는다.

반례: 재현 요청에서는 원본의 확인된 특징을 우선하고, 새 제품 결합 요청에서는 역할에 맞는 변형을 실제로 검증한다. 여러 자료를 모았다는 사실, 모든 금지 요소를 뺐다는 사실, 특정 유사도 숫자만으로 좋은 조합을 증명하지 않는다.

## L. 일정 가정으로 검사 축소 금지

입력: UI 구현의 계약에 코드·시각·행동 검사가 정해져 있다. 에이전트가 작업 시간이 길어졌다는 이유로 시각 비교나 일부 상태 검사를 생략하려 한다. 실제 마감은 주어지지 않았다.

기대 행동: 일정을 임의로 가정하지 않고 정해진 검사 범위·항목·깊이·증거 기준을 모두 유지한다. 시간 부족은 미적용/예외 근거가 아니다. 도구/자료 문제로 실행할 수 없는 검사는 unknown과 구체 사유를 남기고 해결 후 재검증한다. 항목을 삭제하거나 통과로 바꾸지 않는다.

이번 수정에서는 해당 조건을 리뷰·게이트·AGENTS 문장과 수동 대조했다. 새 독립 에이전트 실행이나 제품 검증을 수행했다고 표시하지 않는다.

## M. 복합 제품의 여러 검색·누적과 모바일 탭

입력: 모바일 Todo를 채팅으로도 생성하고 싶다. 채팅 첫 페이지는 대화방 목록/빈 상태뿐이고 has_more=true다. Todo 결과는 따로 조회해야 한다. 나중 결과에 동일 원본이 다시 나온다. 모바일 탭은 큰 회색 채움 버튼 둘로 보인다.

기대 행동: 핵심 Todo 목록/완료·보조 채팅 입력/결과·화면 전환을 B-ID로 나눈다. 조건 교집합은 호출 내부에서 유지하면서 서로 다른 분기는 별도 검색한다. 첫 페이지가 부족하면 다음 페이지나 관련 화면을 확인한다. SC-ID 이력·중복 제거한 R-ID·분기별 D/Q 적용을 누적하고 이전 후보를 지우지 않는다. 탭을 CTA처럼 확장하지 않고 모바일 원본과 선택 표시·높이·라벨·safe area를 비교한다.

반례: 기존 자료가 실제로 충분한 분기는 근거를 확인해 재사용한다. 한 출처가 여러 과제를 실제 충족하면 중복 검색하지 않는다. 접근 제한/끝 페이지/동일 결과를 호출 수 채우기로 반복하지 않는다. 이미지가 첨부되지 않으면 inspected로 바꾸지 않는다. 채팅 결과가 있다는 이유로 Todo 분기를 완료하지 않는다.

## N. 폼 제목·선택형 입력·부모 여백·전 화면 톤·의미 중복

입력: 생성 폼의 h2는 body16px, 라벨은14px. 날짜/시간은 네이티브 기본표현. 완료 첫 행에 부모padding8px+상태margin-top8px. 목록·대화의 표면/입력 스타일이 다르다. 상단2026년9월과 날짜제목9월13일이 인접한다.

기대 행동: 주 제목 시각 역할을 heading 의미 태그와 분리한다. 제품 스타일의 날짜/시간 표시·선택을 연결하되 실제 선택/취소/포커스/저장값을 검증한다. 부모/자식·상태 간격 합을 확인하고 변화를 최소 수정한다. 목록/대화/생성/수정을 같은 폭의 화면 묶음으로 대조한다. 겹치는 월 정보는 줄이되 필요한 연도를 보존한다. 이미지·코드·동작 미실행을 구분한다.

반례: 모든 h2를 h1로 바꾸지 않는다. 네이티브 picker의 OS 팝업까지 꾸몄다고 주장하지 않는다. 모든 여백을 같은 숫자로 강제하지 않는다. 채팅 메시지를 목록 행과 동일한 카드로 강제하지 않는다. 달력 월 이동과 선택 날짜 제목은 역할이 실제로 다르면 함께 존재할 수 있다.

섹션 반례 추가: 서로 다른 날짜 탐색/필터/목록/생성 영역이 한 화면에 있지만 경계가 없다면 과제별 묶음과 간격·표면을 제안한다. 구분선 금지를 모든 경계 금지로 해석하지 않는다. 서비스/작업 단위가 다른 경우 같은 카드 템플릿을 강제하지 않는다(RUI-25).

## O. 불필요한 입력법 설명과 컨트롤 내부 정렬

입력: 빈 composer에 ‘어떤 할 일을 추가할까요?’가 있고 실행 행에는 ‘여러 일은 한 줄에 하나씩’과 전송 버튼이 있다. 안내 삭제 후에도 textarea/footer의 고정 높이가 남아 한 줄 글자가 위로 치우친다.

기대 행동: 필요 없는 상시 입력법 안내와 예약 공간을 함께 삭제한다. 도움/오류 시점에 정말 필요한 안내만 조건부로 제공하고 다중 입력 기능은 유지한다. 한 줄일 때 텍스트·아이콘·버튼의 시각 중심, 여러 줄일 때 위쪽 읽기 시작점과 커서/자동 높이를 구별해 검증한다.

반례: 모든 textarea를 중앙 정렬하지 않는다. 필수 오류·형식 조건을 숨기지 않는다. parent align-items:center나 padding 토큰 존재만으로 실제 내부 정렬을 통과시키지 않는다. 이번에는 문서 조건을 수동 대조했으며 제품 렌더/동작 검증은 수행하지 않았다.

## P. 복합 입력의 이중 포커스

입력: composer의 focus-within 경계와 내부 textarea의 기본 outline이 동시에 나타난다. 전송 버튼도 같은 composer 안에 있다. 사용자는 기본 입력 포커스를 없애도 되는지 묻는다.

기대 행동: 입력 초점 표시 주체를 하나로 정하고 대체 표시가 있는 해당 입력에만 기본 링 제거를 적용한다. 전송 버튼으로 키보드 이동하면 현재 대상이 구별되어야 한다. active는 누름 상태이므로 키보드 포커스 대체로 쓰지 않는다. 오류 표시와 포커스를 혼동하지 않고 고대비도 확인한다.

반례: 모든 input outline을 전역으로 없애지 않는다. wrapper focus-within 하나로 입력과 전송의 초점 차이를 감추지 않는다. 이번 지침 교정은 조건을 수동 대조했으며 제품 포커스 동작을 실제 실행한 결과는 아니다.

## Q. CTA 아이콘의 기본 순서

입력: 전송 버튼이 `↑ 전송` 순서이고 방향/관례상 왼쪽 아이콘이 필요한 별도 이유가 없다.

기대 행동: `전송 ↑`로 명세하고 공통 CTA 컴포넌트의 gap·기본/로딩/비활성 정렬을 확인한다. 뒤로 가기 등 방향을 먼저 보여줄 이유가 있으면 범위와 근거를 남긴다. 아이콘 없는 CTA에 장식 아이콘을 새로 강제하거나 탭·필터 아이콘까지 옮기지 않는다. 문서 조건은 수동 대조했으며 실제 제품 렌더 검증은 별도다.

## R. 공식 Lucide 아이콘 기본 사용

입력: React UI의 전송·편집 아이콘이 필요하다. 비 React HTML 예제에서도 같은 표현이 필요하다.

기대 행동: React는 lucide-react의 설치 버전에서 실제 제공하는 아이콘을 명시적으로 import하고 토큰을 적용한다. HTML은 공식 Lucide SVG/적합한 공식 패키지를 사용하며 React를 도입하지 않는다. 적절한 아이콘이 없다고 path를 임의 제작하지 않는다. 기존 명시 디자인 시스템 예외는 근거를 남긴다. 실제 아이콘 의미·CTA 순서·정렬도 검사한다. 이번 변경은 지침의 수동 대조이며 앱에 패키지를 설치/실행한 결과는 아니다.

## S. 공식 아이콘이어도 동작 의미가 틀린 경우

입력: 예시 선택과 실제 전송 버튼이 같은 ArrowUp 아이콘을 쓴다. 예시 클릭 핸들러는 input.value 설정·크기 조정·focus만 수행하고 전송하지 않는다.

기대 행동: Lucide/오른쪽 배치 여부와 별개로 실제 행동의 불일치를 지적한다. 윤곽선 예시 버튼의 아이콘은 생략할 수 있다. 다른 아이콘으로 바꿀 때도 실제 동작을 설명하는지 확인한다. 클립보드 복사가 없는데 Copy, 화면 이동이 없는데 이동 아이콘으로 기계적으로 교체하지 않는다. 이번에는 제공 화면과 실제 핸들러를 읽어 판단했으며 Todo UI 수정·실행 검증은 하지 않았다.

## T. 갑작스러운 호버와 과한 모션

입력: 버튼 배경이 즉시 바뀌고 hover에만 transition이 있어 해제 때 튄다. 제안 구현은 transition: all과 모든 카드의 확대를 추가한다.

기대 행동: 실제 바뀌는 속성에 기본 상태부터 공통 duration/easing 토큰을 적용하고 진입·해제를 함께 다룬다. 무관한 카드 확대는 추가하지 않는다. 빠른 왕복·연속 클릭, 터치, 키보드, reduced-motion에서 상태와 기능을 보존하는지 실행할 검증을 명시한다. 정지 이미지뿐이면 원본 모션과 구현의 부드러움은 미검증으로 남긴다. 이번 스킬 변경은 지침 검토이며 제품 실행 결과가 아니다.

## U. 화면과 채팅 컨테이너 패딩

입력: .view와 고정 composer는 같은 좌우 토큰을 사용하지만 위아래 패딩은 다르다. 낮은 화면에서 composer가 부모 안의 sticky로 바뀌며 자체 좌우 패딩을 없앤다.

## V. 목록 편집의 적용 범위와 배치

입력: 날짜 제목과 달력이 있는 화면 상단 오른쪽에 ‘편집’이 있다. 실제로는 할 일 행에 수정 버튼을 표시하며, 목록에는 임시 ‘예시 목록’ 문구가 있다.

기대 행동: 목록 편집을 목록 제목/도구 영역에 소속시키고 임시 예시 문구가 없어져도 위치와 의미가 유지되게 한다. 화면 전체 편집으로 오해할 배치를 지적한다. 모든 CTA를 하단으로 옮기거나 편집을 주요 생성 CTA만큼 강조하지 않는다. 빈 목록·필터·날짜 변경·편집 종료·긴 목록의 접근성을 확인한다.

수동 평가: Todo의 헤더와 task-section 구조, editing 조건에서 행 수정 버튼을 추가하는 코드 및 모드 전환 핸들러를 읽었다. 실제 대상은 목록이므로 섹션 소속으로 교정하는 기준이 맞는다. 현재 스킬 변경은 문서와 코드 관찰에 근거하며 제품 이동·실행 결과는 미검증이다.

## W. 같은 범주 안의 행 역할 충돌

입력: Todo 편집 버튼을 화면 헤더에서 목록으로 옮겼지만, 전체/할 일/완료 필터 바로 오른쪽에 같은 크기로 놓았다. 다음 줄에는 수량 요약과 예시 목록 표시가 있다.

기대 행동: 소속 교정만으로 완료하지 않는다. 조회 조건과 편집 모드를 한 줄의 동급 조작으로 묶은 충돌을 지적하고 조회 행과 요약/관리 영역을 구분한다. 예시 표시를 포함한 주변 요소의 필요성과 시선 흐름도 재검토한다. 모든 제품의 복합 도구 모음을 금지하거나 border 변경만으로 해결했다고 하지 않는다.

수동 평가: 사용자 캡처와 todo/index.html에서 list-toolbar가 filters와 edit-list를 함께 감싼 구조를 확인했다. 기존 ‘목록 도구로 묶을 수 있다’ 지침의 부족함을 교정했다. 새 제품 배치의 렌더/행동 검증은 수행하지 않았다.

## X. 사례 좌표가 아닌 판단 관점의 전이

입력: 상품 비교 화면에 비교 대상 선택, 가격 요약, 구매 행동을 배치한다. Todo에서는 필터와 편집을 분리한 실패 기록이 있다.

기대 행동: Todo의 행 구성을 복제하지 않는다. 사용자가 비교하고 결정하는 순서, 각 정보의 필요성, 행동의 적용 범위, 요소 간 관계와 강조를 근거로 묶기/분리/이동/삭제를 판단한다. 서로 다른 역할도 이해를 돕는다면 함께 둘 수 있고 같은 범주도 경쟁하면 나눈다. 실제 화면 증거 없이는 배치 품질을 통과시키지 않는다.

검토 결과: 지침에 판단 순서와 사례/해결 후보 구분을 명시했다. 이번 평가는 문서의 수동 일관성 검토이며 독립 에이전트나 실제 상품 화면의 행동 검증은 아니다.

## Y. 포커스 경계와 내부 영역 안정성

입력: 입력 포커스에서 border가 1px에서 3px로 바뀐다. border-box라 바깥 크기는 같지만 글자가 이동하거나 줄바꿈이 달라진다. 대안은 inset shadow다.

기대 행동: 내부 영역 변화도 실패로 확인한다. 2026-09-20 교정에 따라 입력 컨테이너의 inset shadow를 사용하며 입력 포커스를 border 색 전환으로 대체하지 않는다. 외곽/텍스트/줄바꿈 불변, 이중 경계 없음, 오류+focus, 키보드 즉시 식별, forced-colors 대체 표시, reduced-motion을 확인한다. 모든 border를 없애거나 shadow만으로 모든 환경을 통과했다고 하지 않는다.

검토 결과: 문서상 위 조건과 공식 CSS 근거를 대조했다. 제품 렌더·모션 실행 검증은 하지 않았다.

## Z. DESIGN.md 분석·작성·재사용

입력1: 기존 DESIGN.md에 브랜드와 사용자 확장 섹션이 있고 CSS 토큰 일부가 다르다. 기대: 파일 보존, 문서/코드/현재 요구 대조, 차이의 이유와 관리 원본 명시. 코드를 무조건 정답으로 승격하거나 전체 문서를 외부 예시로 바꾸지 않는다.

입력3: 읽기 전용 리뷰 또는 UI 없는 레포. 기대: 읽기 전용이면 누락과 수정안만 보고한다. 작성 요청의 UI 없는 레포는 범위를 설명하고 임의 색/폰트를 만들지 않는다. 모노레포는 루트에서 앱별 기준을 연결하며 서로 다른 브랜드를 강제 통합하지 않는다.

## AA. hr 없이 탭 선으로 재발한 금지 위반

입력: 탭 아래 전체 폭의 회색 선과 활성 탭의 파란 밑줄이 있다. 구현자는 hr가 없고 선택 표시라 구분선이 아니라고 주장한다.

기대 행동: 구현 방법·반복 횟수·탭 관례와 무관하게 RUI-14 위반으로 판단한다. 선택과 포커스는 유지하면서 선 이외의 표현을 검토한다. 모든 border나 차트 선까지 일괄 삭제하지 않는다. 캡처에서 존재를 확인했어도 CSS 속성을 단정하거나 수정 완료로 보고하지 않는다.

수동 결과: 제공 캡처에서 회색 기준선과 파란 선택 밑줄을 확인했다. mobile.md의 상태선 허용 여지와 design-guardrails.md의 구분선 대안을 발견해 교정했다. 대상 제품 경로는 제공되지 않았으므로 해당 제품 수정/렌더 검증은 하지 않았다.

## AB. 출처 나열 뒤 관성적인 화면으로 대체한 경우

실제 실패: 반려동물 AI 코스 디자인에서 UIbowl 대표 화면들을 관찰하고 출처를 인용했지만, 생성 결과는 큰 사진·녹색 박스·둥근 버튼을 반복했다. 사용자는 “디자인 AI 같은데? 레퍼런스 하나도 반영 안 된 거 같음”이라고 지적했다. 이후 HTML로 변경한 결과도 전체 품질 검증 완료나 사용자 승인으로 간주하지 않는다.

| 입력 | 기대 행동 | 실패 판정 |
|---|---|---|

## AF. 각색에서 색의 역할과 전체 스타일을 잃은 경우

실제 입력/실패: 반려동물 카페의 탐색·테마·예약을 레퍼런스와 결합했다. P1–P3는 크림/초록과 동일 중립 퀵메뉴를 선택했고 사용자에게 색·배치·느낌·스타일 손실을 지적받았다. 이어진 원본 주황색 복구 해석도 “색 커스텀은 필요하지만 선택 관점이 필요”하다는 교정을 받았다.

기대: 원본에서 관찰한 강조 면적·명도/채도 대비·사진/그림/조작 차이·그룹 간격을 공유 계약에 두고, 해석 가설과 제품의 선택값을 구별한다. 실제 전체 화면과 요소를 모두 비교한다. 부분 기능/배치 판정을 전체 스타일 통과로 확대하지 않는다. 정확한 재현 요청의 원본색, 무채색 원본의 차분한 대비, 광고가 필요 없는 제품이 반례다. 청색·다색 그림·36px 간격을 보편 규칙으로 복제하면 실패다.

[실제 교정 및 검증 한계](results/reference-decompose-round-04.md), [스킬 진단](results/reference-style-contract/)을 참조한다. 실제 사용자 실패와 독립 반복 실험의 수행 여부는 구별한다.

## AG. 반복 컨트롤의 상태가 형제 치수를 바꾸는 경우

실제 실패: P4 예약 날짜 중 마감일에만 보조줄을 넣어 해당 버튼과 같은 grid 행 전체가 늘었다. 사용자는 선택 불가로 표현하고 상태 때문에 다른 요소가 늘어나지 않게 고치라고 요청했다. 같은 후속 작업에서 카페 단위 교대표면, 입장조건 정보 태그/아이콘, 셀렉트 커스텀도 요구했다.

기대: 반복 컨트롤의 상태별 추가 내용 자리와 부모/형제 최종 박스를 계약하고, 기본·선택·불가가 섞인 상태/좁은폭/확대를 실제 비교한다. 불가 이유가 판단에 필수면 일관된 설명 공간이나 그룹 설명을 유지한다. 일반 긴 본문·펼침까지 고정높이/잘림으로 바꾸면 실패다. 목록 교대표면은 제품 선택이며 보편 강제가 아니다. 태그는 정보/행동 의미와 조건 중복을 구별하고, 셀렉트의 닫힌필드만 바꿨으면 네이티브 팝업까지 커스텀했다고 하지 않는다.

[실제 결과와 진단 범위](results/reference-controls-p5.md), [입력 P5](../design/reference-language/round-04/prompt-v5.md)에 연결한다.

AG 후속 입력: 태그를 추가한 오른쪽 정보128px 아래에 이동가방 조건이 있고 사진만112px이다. 공유행 하단관계가 요구되면 정보/사진 높이소유권과crop을재검토한다. 짧은사진을의도한원본이나내용자연높이를모든행고정높이로억제하는것은반례다.


## AH. 공간이 좁은 보조정보12px 예외와 가로 시간 선택

사용자 명시 변경: 기본14px를 유지하되 특별히 공간이 부족한 경우12px도 허용하고 남용하지 않는다. 이번 태그/조건요약12px는 가격·행동·입력14px와 별도이며 같은 중요조건은 상세/확인에서14px 이상으로 제공한다. 예외의 선택자·이유·computed값·좁은폭/확대 판독을 기록한다. 모든 메타데이터/모바일/버튼/본문을 자동12px로 바꾸거나12px미만으로 내리면 실패다.

사용자 시간 선택 변경: 많은 시간은 짧은 가로 버튼으로, 스크롤바는 숨기고 다음 항목의 부분 노출로 넘김을 드러낸다. 페이지 전체가 밀리는 grid 최소폭, 끝시간 선택 후 수정에서 가려지는 선택값, 청색 위 청색 focus를 실제로 발견해 수정했다. 실제 터치/가로휠/Tab/끝시간선택/요약·복귀·확대·고대비를 확인한다. 항목이 적어 모두 보이거나 세로 비교가 적합한 제품에 가로스크롤을 강제하지 않는 것이 반례다.

## AI. 토글 데이터만 바뀌고 실제 활성 표현은 그대로인 경우

## AM. 탐색 화면을 저장에 그대로 복제한 경우

P10 저장: 중복 제목/날짜/강한 시간 CTA를 제거하고 식별·소개·조건으로 비교하며 상세에서 예약한다. 빈 상태는 남은 화면 중앙에 둔다. 양폭 상세예약/해제/빈복구를 검증했다. 날짜가 저장 대상의 식별자이거나 즉시 실행이 핵심인 제품에 같은 생략을 강제하지 않는다. [판독](../design/reference-language/round-04/gate-review.md).

## AN. 짧은 내용에도 스크롤이 생기는 경우

P11: 저장 빈 상태/1개목록 양폭에서문서높이=viewport,휠scrollY0을확인한다. 항목증가/확대시에는필요한스크롤과끝행동접근을보존한다. 숨김으로내용을자르면실패다. 예약위계/복구를포함한 [P11 검증](../design/reference-language/round-04/gate-review.md)에결과를연결한다.

## AO. 내역의 기간·수량·행동 대상이 불명확한 경우

P12사용자교정: 중복그룹제목을제거하고항목상태만유지하며카페명취소버튼과기간/건수/방문일범위를연결한다. 다른달표본으로1/3/12개월조회결과1/2/3건,취소후수량유지와상태변경,재로드·빈기간복구를검증했다. 기간과무관한제품에필터를강요하거나표시만바뀌고데이터가안바뀌면실패다. [판독](../design/reference-language/round-04/gate-review.md).

## AQ. 아이콘 순서·누락·묶음 중심과 맥락 있는 아이콘 버튼

Round8 실제 실패: 카메라/앨범 행동의 아이콘 간격이 넓었고, 외부 SVG가 안 보이는데22px 슬롯이 남아 라벨 중심이 버튼 중심에서 약17px 벗어났다. 사용자는 관례에 맞는 순서와 약4px 간격을 요구했고, 다른 재료 추가 버튼에는 오른쪽 plus를 명시했다. 상단 사진 등록은 맥락상 카메라 아이콘만으로 충분하다고 교정했다.

기대: 동작 식별과 방향 표시, 명시 순서, 실제 보이는 묶음의 중심을 별개로 판단한다. 아이콘 정상/누락·긴 라벨·좁은 폭에서 자리와 간격을 확인한다. 아이콘만 쓸 때도 접근 가능한 이름과 조작 영역을 유지한다. 모든 동작 아이콘을 왼쪽으로 바꾸거나 모든 제품 간격을4px로 고정하면 실패다. [실제 회귀와 독립 설계 표본](results/round8-feedback.md).

## AR. 표면 삭제와 필터 변화가 항목·주행동을 흐리는 경우

Round8 내부 검수에서 재료 표면을 불필요한 카드로 판단해 제거한 뒤 사용자가 항목 구분 부족을 지적했다. 냉장고 전체 재료에 적용되는 요리 보기 버튼도 필터별 행 수에 따라 움직였고, 재료 추가는 목록 제목·개수 옆으로 이동해 달라고 요청했다.

기대: 표면 삭제 전후의 이름·수량·행동 소속을 비교한다. 전체 재료와 필터 결과 중 행동의 실제 대상을 먼저 확인하고, 안정된 조작 위치와 마지막 항목 접근을 함께 검증한다. 고정 CTA를 선택하면 빈/긴 목록·필터·확대·하단 탐색과 겹침을 확인한다. 모든 목록에 배경이나 고정 CTA를 강제하지 않으며, 제목·개수 태그를 모든 화면에 복제하지 않는다. [실제 회귀](results/round8-feedback.md).

## AS. 전달한 HTML 진입점이 비어 있는 경우

Round8은 HTTP에서 확인한 ES module 진입점이 직접 파일 열기에서는 막혔다. 사용자가 실제로 여는 경로를 확인하고, 지원하는 진입 방식별 최초 렌더와 다음 행동을 검증한다. 서버가 필수인 제품을 독립 파일로 강제 변환하는 것은 반례다. 직접 파일을 지원하도록 결정한 이번 정적 앱은 file/HTTP 두 방식의 렌더·이동을 확인했다. [검증 범위](results/round8-feedback.md).

## AT. 랜딩의 일부 검사 통과를 전체 구성 완료로 확대한 경우

Round9 실제 실패: 문서 예시·FAQ·작성 진입을 구현하고 게이트 PASS를 보고했으나 푸터는 서비스명과 링크 하나로 끝났다. 사용자는 기본 푸터도 갖추라고 교정했다. 기대: 진입부터 페이지 끝과 연결 도구까지 영역·사용자 목적·실제 목적지를 계약하고 빠진 영역을 확인한다. 서비스 규모에 맞는 하단 정보와 실제 링크를 제공한다. 미확정 회사/정책/연락처를 만들거나 편집 도구에도 다열 푸터를 강제하면 실패다.

## AU. 여러 제품의 교정을 단일 배치 규칙으로 축소한 경우

입력: Round8에서 카메라 아이콘의 넓은 간격·빈 슬롯, 재료 구분 부족, 필터별 이동 CTA, 파일 진입 실패를 교정했고 Round9에서는 랜딩의 하단 구성이 부족했다. 두 라운드를 합쳐 스킬에 반영한다. 기대: 이미 반영한 지침과 새 보완을 구별하고 각 문제의 적용 조건·반례·실제 증거를 연결한다. 모든 아이콘4px/왼쪽, 모든 CTA 고정, 모든 화면 다열 푸터 같은 처방은 실패다. 실제 제품 재검증·문서 형식 검사·독립 명세 평가를 구별한다. [종합 결과](results/round8-9-learning.md).

## AV. 정적 상태 표본과 복구 성공의 차이

합성 입력: 폼 저장 실패 후 재시도는 성공하지만 중복 저장 여부는 모른다. 로딩 직후 필터 이동으로 실패 안내가 사라진다. 기대: 응답 유실/실제 미저장, 입력 보존, 중복 반영, 오래된 응답, 안내·초점 복귀를 하나의 연속 시나리오로 검증한다. 정적 컴포넌트나 서버가 없는 명세에서는 이를 새 기능으로 구현하지 않고 미검증/의존성을 구별한다.

## AW. 토큰 연결만으로 사진 위 대비를 통과시키는 경우

합성 입력: secondary 텍스트가 disabled 경계를 참조하고 opacity .6으로 사진 위에 표시된다. 정지 캡처로 PASS를 요구한다. 기대: 역할 결합·부모 합성·사진 크롭·필요한 테마/상태를 분리해 측정하고 캡처 범위 밖은 미검증으로 둔다. 낮은 opacity 자체를 실패로 단정하지 않는다. APCA 점수나 이미지 글자 가장자리 샘플을 WCAG 전체 통과로 바꾸면 실패다.

## AX. hover 말줄임과 폰트 교체

합성 입력: 긴 한글 제목을 말줄임하고 hover tooltip을 제공했다. 320px 터치·키보드와 폰트 미로드를 검토한다. 기대: 전체 값 접근·동일 접두어 항목 식별·fallback/실제 폰트·줄바꿈·초점 복귀를 확인한다. 16px 선언 후 transform 축소로 하한을 우회하지 않는다. 고정 문구 버튼에 임의로 긴 사용자 본문을 넣거나 시스템 글꼴에 웹폰트를 추가하는 것은 반례다.

## AY. AI 탐지에 잡힌 사실과 정당한 반복

합성 입력: “혁신적인 화면에서 직관적으로 검색하세요. 검색 40% 단축(내부 실험, 20명, 기존판 대비). 실패하면 조건을 유지한 채 다시 검색할 수 있어요.” 문구만 수정한다. 기대: 군더더기를 줄이고 수치·실험 조건·가능성을 보존한다. 단축 대상이 불명확하면 검색 시간이라고 만들지 않는다. 달력의 균일 gap, 브랜드 serif, 실제 순서의 01/02는 맥락과 기존 규칙을 대조하며 스캐너 일치만으로 삭제하지 않는다. 억제/제외로 0건이 된 것을 시각 PASS로 보고하면 실패다.

## AZ. 변경 귀속과 삭제 신호

합성 입력: 공통 카드 CSS 변경 뒤 오류 라벨·선택 배경이 사라졌고 키보드 결함은 전부터 있었다. 기대: 실제 원인과 전후 결과로 신규/회귀/기존/발생 미확인을 구별하고 소비 화면을 추적한다. 기존 결함도 현재 제품 게이트에는 남는다. aria-label→유효한 aria-labelledby의 동등한 대체는 삭제 줄만으로 회귀가 아니다. 공유 토큰이 바뀌어 손대지 않은 소비 코드가 깨진 경우도 회귀일 수 있다.

## BA. 효과 설명과 대안 비교의 근거

합성 입력: 정지 화면의 빛 효과를 정확한 CSS/라이브러리로 설명하라고 한다. 이어 기존 예약 목록의 밀도 두 대안을 비교하고 구현 방향을 위임한다. 기대: 정지 화면은 가능한 재현 가설이며 실측/계산/가설·레이어 역할을 구별한다. 대안은 같은 내용·기능·주변 맥락에서 밀도 축을 비교하고 선택 근거·비용을 남긴다. 실제 렌더 없는 spec-only 평가에서는 품질 통과를 주장하지 않는다. 색 비교 자체를 요청하면 색을 비교 축으로 허용하며 매번 세 후보나 별도 승인을 강제하지 않는다.

AV–BA는 [외부 스킬 보완 평가](results/external-skills-2026-09-14/results.md)에 연결한다. 합성 입력이며 새 실제 사용자 실패로 기록하지 않는다.

## BB. 작은 버튼의 유효 클릭 영역 확장

합성 입력: 20px 아이콘/버튼이 gap4px로 배치돼 있고 pseudo-element를44px로 확장했다. 기대: 중앙뿐 아니라 경계·이웃 사이를 눌러 어느 행동이 실행되는지 확인한다.44px 선언으로 통과하지 않으며 레이아웃/클리핑/이벤트 전달을 대조한다. 20px+4px가 최소 기준의 간격 예외에 해당할 수 있다는 사실과44px로 확장해 충돌하는 것은 구별한다.

## BC. 아이콘 색·채움 일괄 변경

합성 입력: 다색 브랜드 아이콘과 Lucide 북마크를 모두 currentColor/fill로 통일한다. 기대: 단색 기능 아이콘과 브랜드 자산의 역할을 구별하고 지원하는 상태 형태를 사용한다. 임의 fill로 깨진 그림, 색만으로 상태 구분, 중복 낭독은 실제 확인한다. 고정 stroke·반전·애니메이션을 모든 아이콘에 강제하지 않는다.

## BD. 오래된 CTA 기본 순서의 재발

실제 문서 실패: ui-composition/AGENTS는 역할·관례 중심인데 design-tokens에는 label→icon 기본이 남아 있었다. 기대: 토큰 문서는 단일 구성 기준을 참조하고 카메라 선행/다음단계 후행·명시 순서를 함께 지원한다. 한 파일만 최신이라고 전체 일관성을 통과시키지 않는다.

## BE. 넓은 화면 안의 좁은 컨테이너

합성 입력:1440px viewport의320px 사이드 패널 카드가 넘치지만768px media query는 발동하지 않는다. 기대: 실제 가용 폭·형제 최소폭·긴 내용·container query 필요성을 판단하고 전환 직전/직후를 확인한다. 모든 media query를1024로 바꾸거나 충분한 구조를 조기에 접지 않는다.

## BF. 겹친 카드 행동과 순서·터치 상태

합성 입력: 카드 링크 위 저장 버튼, CSS order로 이동한 조작, 터치 후 남는 hover가 있다. 기대: 박스 겹침과 유효 이벤트 영역을 구별하고 이중 실행/중첩 interactive DOM을 피한다. 시각·DOM/Tab 순서와 hover/selected/focus를 실제 대조한다. 닫기 행동이 있는 모달 배경까지 pointer-events:none으로 바꾸지 않는다.

BB–BF의 [후속 평가](results/external-skills-2026-09-14/icon-layout.md)는 문서 적용과 실제 제품 실행을 구별한다.

## BG. 입력 자체에 포커스 표시가 남는 재발

입력: 검색 필드는 아이콘과 input을 감싼 컨테이너, composer는 textarea와 전송 버튼을 감싼 컨테이너다. 입력 자체에 inset shadow가 적용돼 있다. 사용자는 입력을 감싸는 테두리에 border 대신 안쪽 그림자로 초점을 표시하라고 요청한다.

기대: 실제 DOM 초점은 입력에 유지하고 시각적 강조만 필드 컨테이너의 inset box-shadow로 옮긴다. 내부 기본 outline/라이브러리 ring은 컴포넌트 범위에서 제거한다. 전송 버튼으로 Tab 이동하면 입력 강조를 해제하고 버튼 초점을 구별한다. 기본/오류 border는 두께를 유지하고 키보드·고대비 대체 표시를 보존한다.

실패: input 자체에 inset을 유지, 컨테이너 border 색 변경만 적용, 폼 전체에 강조, wrapper tabindex 추가, blur 사용, 무조건 focus-within으로 전송 초점까지 동일 표시, 전역 outline 제거.

반례: 일반 버튼/링크에 이 입력 전용 방식을 강제하지 않는다. forced-colors의 시스템 outline 대체는 허용한다. [수동 시나리오 판정](results/input-container-focus.md)을 실제 브라우저 검증과 구별한다. 기존 Y의 border 대안은 이번 교정 이후 입력 포커스에는 적용하지 않는다.


## BH. 통합 호출의 발견과 요청별 범위

## BACKGROUND-01 — 흰 기본 배경과 명시 다크 요청

반례: 사진·버튼·입력·상태색까지 모두 흰색으로 치환하지 않는다. 기존 제품을 요청 없이 일괄 수정하지 않는다. 읽기 전용은 충돌·수정안 전달, 명세 전용은 실제 배경 렌더 미검증으로 유지한다.
