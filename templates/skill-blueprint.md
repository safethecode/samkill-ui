# 새로운 레퍼런스 스킬 작성 틀

이 파일은 설치되는 스킬이 아닌 작성용 보일러플레이트다. 새 스킬의 이름으로 폴더를 만들고 아래 구조를 과제에 맞게 작성한다. 현재 5개 스킬의 실패 사례와 겹치는지 먼저 확인한다.

```text
skill-name/
  SKILL.md
  agents/openai.yaml       # 선택적 표시 이름과 호출 예시
  references/              # 해당 작업에 필요한 상세 자료만
```

SKILL.md의 frontmatter는 `name`과 `description`을 갖는다. 이름은 소문자/숫자/하이픈으로 구성한다. description은 언제 선택해야 하는지를 구체적으로 설명하며 범용 UI 요청을 무조건 끌어들이지 않는다.

## 본문 작성 순서

1. **목적:** 반복되는 실제 실패와 이 스킬이 바꿀 판단을 한두 문장으로 쓴다.
2. **입력:** 사용자 과제, 자료, 기존 결과물 중 필요한 것. 빠졌을 때 가정할 것과 미확인으로 남길 것을 구분한다.
3. **근거:** 어떤 자료를 실제로 확인할지, 관찰·해석·새 결정을 어떻게 분리할지 쓴다.
4. **결정:** 채택할 원칙, 피할 선택, 충돌 시 제품 요구를 적용하는 조건을 쓴다. 금지마다 이유와 대안을 붙인다.
5. **결과물:** 후속 작업이 읽을 ID·출처·상태·검증 슬롯을 정의한다. 이미 있는 형식과 호환되게 한다.
6. **실행과 검증:** 실제 도구/화면으로 확인할 행동을 쓴다. 명세 검토와 실제 검증을 구분한다.
7. **종료:** 완료·부분 완료·미검증 상태와 다음 필요한 작업을 쓴다. 스킬이 별도 외부 전송 권한을 만들지 않는다.
8. **예시:** 짧고 완성된 사례 한 개를 넣는다. 합성 자료면 명확히 표시한다.

## 확장 예시

검색 결과 화면의 필터 설계가 계속 누락되면 `search-filter-flow`처럼 독립 과제로 만든다. 입력은 검색 과제/필터/결과 상태, 산출물은 적용 중 필터·0건 복구·뒤로 가기 정책이다. 기존 `samkill-onboarding-flow`에 검색 UX 지침을 쌓아 넣지 않는다.

금융·커머스의 버튼 밀도 차이처럼 같은 판단의 변형이면 해당 스킬의 references에 추가하고 읽을 조건을 본문에 연결한다. 모든 스킬에서 모든 참고 문서를 로드하지 않는다.

## 배포 전

`eval-case-blueprint.md`로 실제 사례를 정하고, 스킬 없이 실행한 결과의 실패 또는 누락을 기록한다. 최소 지침을 작성하고 같은 입력으로 독립 평가한다. 기존에 잘했던 판단도 회귀 확인한다. frontmatter/링크/스크립트(있는 경우)를 검증한다. 외형 단어의 존재 여부만 검사하는 테스트로 디자인 품질을 판정하지 않는다.
