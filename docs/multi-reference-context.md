# 2026-09-06 여러 레퍼런스와 모바일 구성 후속 맥락

이 기록은 스킬 개선 중 사용자가 이어서 보낸 요청을 함께 보존한다. Todo 제품 코드를 수정한 기록은 아니다. 기존 `docs/session-context.md`에는 다른 작업에서 추가한 Todo 재구현 기록이 이미 있어 그 내용을 변경하지 않았다.

## 여러 레퍼런스 누적

사용자는 “채팅”을 말하면 채팅만 검색하고 핵심 Todo 목록 자료를 가져오지 않는 문제를 지적했다. 여러 MCP 호출로 자료를 누적하고 실제로 적용해 달라고 요청했다.

기존 연구 스킬에는 첫 페이지 고정, 사용자의 추가 요청 때만 다음 페이지, 0건 한 번만 재시도라는 제한이 있었다. 하나의 검색 의도에 여러 필터를 함께 전달하라는 규칙을 제품 전체의 호출 제한으로 확대하면 복합 과제가 누락된다. 이를 과제 분기(B-ID), 호출 이력(SC-ID), 누적 출처(R-ID), 구현/품질 연결(D/Q-ID)로 바꿨다.

Todo 목록/완료, 대화 입력/결과, 모바일 화면 전환을 각각 조사한다. 실제로 필요한 분기의 자료가 없으면 추가 호출과 페이지 탐색을 진행한다. 이미 적합한 자료가 있으면 확인해서 재사용하되 과거에 앱 이름을 적었다는 사실만으로 충분하다고 하지 않는다. 반환 결과가 많아도 핵심 분기가 비어 있으면 조사 완료가 아니다. 접근 제한을 우회하거나 소진된 검색을 무한 반복하지 않는다.

[검색 계획](../skills/samkill-uibowl-research/references/research-plan.md)에 누적 표와 종료 기준을, [검색 예시](../skills/samkill-uibowl-research/references/search-examples.md)에 Todo와 채팅의 별도 호출을 넣었다. RUI-18로 분기 누락·누적 유실·마지막 출처만 적용하는 실패를 추가했다.

## 실제 MCP 확인 범위

`search_ui_patterns`를 실제 3회 호출했다: `할 일` page1, `채팅` page1, 같은 `채팅` page2. 모두 MOBILE/limit3으로 실행했고 각 호출의 대표 이미지 3장씩 총9장을 직접 확인했다. 정지 대표 이미지만 관찰했으며 전체 이미지 묶음이나 전송/복구 동작을 검사하지 않았다.

Todo 검색은 럽맘·투두메이트·오늘의 루틴, 채팅 첫 페이지는 마이리얼트립·미소·헬로우봇, 다음 페이지는 수현이랑·토스증권·빼기였다. 첫 채팅 결과가 대화방 목록/빈 상태 위주인 점을 보고 다음 페이지로 진행했다. 다음 페이지에서 입력/전송 조작과 상담 시작 메시지 후보를 확보했다. Todo 생성에 필요한 전체 대화·상태·전환 자료가 완성됐다고 주장하지 않는다.

호출 인자·페이지·분기·9개 R-ID·원본 링크·관찰·제외 이유는 [실제 호출 기록](../evals/results/multi-reference-live.json)에 누적했다. 서명 URL/인증 토큰과 불필요한 사용자 정보를 저장하지 않았다. 이는 다중 호출·페이지 진행·관찰 기록을 실제 확인한 통합 검사이며 제품 품질의 증거가 아니다.

## 2026-09-06 폼·패딩·화면 통일 피드백

사용자는 이어서 화면 캡처와 함께 다음을 교정했다.

| 사용자 관찰/요구 | 확인한 근거와 반영 |
|---|---|
| 모바일 탭이 앱스럽지 않음 | 첨부 화면은 선택 셀 전체의 큰 회색 면과 가로 아이콘/라벨을 보여준다. 로컬 `.view-tabs`는 min-height80px, 자식 flex와 전체 선택 배경을 사용한다. RUI-19와 모바일 기준에 목적지에 맞는 위치, 선택 표시 면적, 아이콘/라벨, 높이/safe area의 대조를 추가했다. 모든 탭을 세로로 만들라는 고정 규칙은 아니다. |
| ‘할 일 추가’는 대제목이어야 함 | 첨부 생성 폼 제목이 라벨/입력 대비 충분히 강조되지 않는다. 로컬 공통 h2는 body16px, dialog-title은 h2다. RUI-20은 의미 heading과 시각 주 제목 역할을 분리하고 폼 제목도 공통 주 제목 위계로 검증한다. |
| 날짜·시간 입력을 제품 스타일로 커스텀 | 첨부에 `09/13/2026`, `--:-- --`와 브라우저 기본 아이콘이 보인다. 로컬 input type=date/time을 확인했다. RUI-21은 표시/트리거/선택 경험의 스타일과 실제 선택·취소·초기화·포커스·저장값을 함께 검사한다. |
| 부모 컨테이너 패딩이 맞지 않는 듯함 | 첨부 완료 행의 상하 바깥 여백이 다르게 보인다. 코드에는 `.tasks` padding8px와 `.task.is-done` margin-top8px가 있어 첫 완료 행의 위쪽에 두 간격이 더해질 수 있다. 실제 DOM 재측정을 수행하지 않았으므로 최종 계산값을 측정했다고 주장하지 않는다. RUI-22는 부모/자식/상태의 합과 첫/마지막 행을 검사한다. |
| 채팅이 다른 화면과 톤이 맞지 않음 | 사용자가 제공한 대화 전체 화면은 넓은 흰 표면, 설명과 입력, 큰 탭을 보여준다. 코드에는 목록의 표면 묶음과 별도의 chat-view/composer 표현이 있다. RUI-23은 목록/대화/폼의 동일 역할을 실제 화면 묶음으로 비교한다. 공통 토큰 사용만으로 통일 완료가 아니다. |

첨부 이미지는 대화에서 직접 관찰했다. 캡처 임시 경로에서 별도 파일 복사를 시도했으나 당시 경로에 파일이 없어 보존 이미지를 만들지 못했다. 따라서 이 문서의 관찰과 읽기 전용 코드 근거를 남기며, 존재하지 않는 이미지 파일을 검증 증거로 링크하지 않는다. Todo 코드와 기존 판독 결과는 수정하지 않았다.

## 2026-09-06 날짜 정보 반복 교정

사용자는 `2026년 9월` 설명과 그 아래 `9월 13일 할 일` 제목이 겹친다고 지적했다. 글자 그대로 같은 문자열만 중복으로 잡는 것은 부족하다. RUI-24와 UX 문구 계약에 날짜·수량·상태를 의미 단위로 비교하도록 추가했다. 불필요한 보조 줄을 합치거나 없애되 필요한 연도처럼 고유 정보는 보존한다. 달력 월 탐색 등 실제 다른 역할이 있으면 그 이유를 확인해 별도로 표시한다.

## 개정과 검증

이번 catalog v3는 v2의 67개 규칙을 그대로 보존하고 RUI-18–25를 추가한 총75개다. 원본50개 + 추가25개이며 이번 작업 중69개/73개는 중간 수량이다. 스킬 연구·구현·리뷰·문구, 모바일/토큰 기준과 AGENTS에 연결했다. 일정이나 소요 시간을 이유로 기존 검사를 축소하지 않는다.

[독립 적용 평가](../evals/results/multi-reference-green.md)는 모의 검색 결과로 분기·중복 보존·추가 탐색·인계와 보고된 UI 문제에 대한 설계 판단을 확인한다. 이 평가는 실제 MCP 호출 기록과 분리하며 가상 결과에 실제 이미지 관찰 상태를 붙이지 않는다. 최종 catalog75개 기준 CLI21개 테스트가 통과했다. 문서 링크121개와 스킬5개 YAML/메타데이터, 이전67개 규칙의 내용 보존, 실제 MCP3회/고유 출처9개의 누적 기록과 서명 토큰 미저장을 확인했다. 문서 변경의 diff 공백 검사도 통과했다.

## 2026-09-06 서비스별 섹션 구분

사용자는 목록 전체 화면을 보며 각 컨테이너/섹션이 구분되기를 요청했고 방식은 서비스마다 다를 수 있다고 명시했다. RUI-25를 같은 catalog v3 개정에 추가했다. 날짜 탐색·상태 필터·목록·생성의 과제 관계를 먼저 정하고 내부/외부 간격·제목·표면 단계로 묶는다. 구분선 금지를 경계 없는 화면으로 해석하지 않으며 모든 영역을 일률적인 카드로 감싸지도 않는다.
