## 실패 기준 보존과 적용

이전 문서의 “보라색·둥근 모서리·그라디언트 자체는 결함이 아니다”라는 표현은 원본에서 실패로 규정한 항목을 일반론으로 해제할 수 있었다. 해당 표현과 자동 허용 판단을 철회한다. 실패 여부는 원본 기준, 이번 제품의 적용 범위, 실제 구현 근거로 판독한다.

[실패 목록](../skills/samkill-reference-review/references/failure-catalog.json)에 design.md의 Known AI Failure Patterns 16개, QA Guardrails 24개, AI Slop 체크리스트 10개를 원문 그대로 보존했다. 각 항목에 고정 ID, 원본 경로·제목·시작 줄·파일 SHA-256을 남겼다. 원본의 수치 기준도 임의로 완화하지 않는다. 아래 구분은 실패 기준을 삭제하는 이유가 아니다.

| 검토 대상 | 적용 방식 |
|---|---|
| 원본의 금지 항목·반경·그림자·색·여백 기준 | 먼저 적용 대상으로 등록한다. 명시된 브랜드나 과제와 충돌하면 관련 규칙 ID와 충돌 범위, 근거, 대안, 검증 자료를 예외로 기록한다. “취향 차이”만으로 통과시키지 않는다. |
| 서로 충돌하는 기준 | 두 원본 ID를 모두 남기고 이번 화면에서의 우선순위와 영향을 결정한다. 조용히 한쪽을 삭제하지 않는다. |
| 이름만 있는 제품 DB·실제 제품 전체에 대한 단정 | 원본 규칙은 보존하되 현재 제품에서 직접 관찰한 사실과 구별한다. 제품 이름만으로 토큰을 실측값이라고 주장하지 않는다. |
| 여러 레퍼런스 혼합·카드 형태 변화 | 사용자 과제와 정보 역할을 먼저 정한다. 재현 범위와 충돌하는 원본 조건은 미적용 또는 예외의 구체적 사유를 남긴다. |
| 수정 범위·상호작용·밀도 | 원본 위반 여부를 먼저 기록한다. 실제 과제 영향과 터치·키보드·뷰포트를 검증해서 수정 방법을 정한다. |
| 머릿속 렌더링·빌드 성공 | 시각 검증을 대체하지 못한다. 화면이나 행동을 확인하지 못했으면 미검증으로 남긴다. |

## 반복 판단과 실패 누적

[디자인 게이트](../skills/samkill-reference-review/references/design-gate.md)는 모든 활성 규칙, 프로젝트 제외 항목, 제품 완료 조건을 계약에 포함하도록 한다. 각 항목의 적용 여부와 이유를 남기며, 누락·미확인·오래된 증거·선언하지 않은 예외는 통과하지 못한다. 적용되는 제외 항목이 구현에 들어가면 실패다.

프로젝트의 이전 실패와 수정 후 재검증 결과를 JSONL 이력에 추가한다. 고쳤다고 과거 실패를 지우지 않는다. 새 실패에는 PROJECT-ID와 재현 조건·사용자 영향·근거·수정·재발 방지 항목을 붙인다. 반복되는 패턴은 반례와 적용 범위를 검토해 공통 목록에 승격한다. 규칙을 바꿀 때는 버전을 올리고 이유와 대체 규칙을 남긴다.

판독 스크립트는 판독 기록의 누락과 증거 무결성을 검사한다. 실제 시각 판단은 코드·렌더링·상호작용을 확인한 리뷰어가 수행한다. JSON에 통과라고 썼다는 사실만으로 좋은 디자인을 증명할 수 없다.

## 디자인 방향

목표는 레퍼런스와 아이디어를 결합해 사용자의 일을 잘 해결하는 제품을 구현하는 것이다. 고객 문제와 핵심 행동을 먼저 정의하고, 요소마다 필요한 정보와 배치·강조 이유를 연결한다. 레퍼런스에서는 구체적인 시각 규칙과 문제 해결 방식을 추출하고, 아이디어는 해결할 마찰과 확인할 행동을 명시해 더한다.

제품 기준과 디자인 기준을 따로 확인한다. 제외 항목을 없앤 것만으로 완성되지 않으며, 개성을 이유로 실패 기준을 우회하지도 않는다. 의도한 브랜드 표현과 새 아이디어는 충돌하는 규칙의 범위를 명시하고 실제 사용성과 함께 검증한다.

## 범위와 완료 기준

5개 스킬: uibowl-research, reference-to-ui, reference-review, ux-copy, onboarding-flow.
각 스킬은 입력, 관찰 근거, 판단, 전달 결과, 중단/미검증 상태를 명시한다. 공통 패턴은 전달 문서의 evidence ID로 이어지며 필수 외부 스킬 의존성을 만들지 않는다. 추가 스킬용 템플릿과 회귀 평가 사례를 함께 제공한다.

## 한국어 UX 문구 추가 입력

사용자가 대화에 제공한 김자유(토스 UX Writer)의 「토스의 8가지 라이팅 원칙들」(2022-11-15) 본문을 기준으로 문구 지침을 보완한다. 최신 공식 정책이라고 주장하지 않으며, 댓글·메뉴·푸터·로고 표기는 원칙 자료에 포함하지 않는다. 명확함·간결함·친근함·존중·공감을 기반으로 8개 원칙을 한국어 점검 질문과 가상 UI 전후 예시로 바꾼다. 원문 전체를 패키지에 복제하지 않는다.

로컬 humanize-korean의 번역투/명사화/피동 관련 패턴도 참고했다. 이 요청은 기사 윤문이 아니라 제품 문구 스킬 제작이므로 장문 윤문 변경률·문장 리듬 강제·격식 무조건 보존 같은 규칙은 가져오지 않는다. 가능성과 불확실성을 나타내는 표현을 무조건 단정으로 바꾸는 규칙도 적용하지 않는다. 사실과 제품 동작을 먼저 보존하고 자연스럽게 고친다.
